- UUID 键规范小写，设备 ID、规范化时间和去首尾空白用途组成 JSON 数组后取 SHA-256。首次 201、同键同内容 200、同键不同内容 409；重放优先于后来变化的资源/时间可用性检查，但仍须有效学生账号。
- 状态机在 Service 层统一执行角色、归属、前态、时间和必要的资源检查；条件 UPDATE 校验影响行数，主表与 CREATE/APPROVE/REJECT/CANCEL/REVOKE/EXPIRE/COMPLETE 审计原子提交。相同操作者、最后动作及规范化原因的重试不增加日志。
- READ COMMITTED 下按实验室→设备→学生→预约加锁；授权替换、资源状态与预约共享现有资源锁。锁超时/死锁由统一数据库异常返回 503，全部回滚，不使用内存锁或无限重试。
- 已移除 FoundationResourceStateGuard，由唯一的 ReservationResourceStateGuard 查询真实有效预约；设备维护/停用、实验室停用有占用时返回 409，并与新预约创建互斥。
- 每分钟过期作业，每批 200、每轮至多 2000，每条独立事务，锁后重查状态；失败下轮重试。重复执行无重复日志。查询及统计将到时 PENDING 视为有效 EXPIRED，不依赖调度准点，也不无锁改库。
- 统计按创建日期归属，日期包含两端最多 90 天；MySQL 聚合总数、当前待审批、已通过、按日趋势、热门设备前十；趋势补零，实验室管理员 SQL 限制范围。不是设备真实利用率。

### 真实并发与原子性证据

- 两学生同设备同时间：1 个 201、1 个 409，数据库仅一条预约。
- 六次同学生同键并发：1 个 201、5 个 200，只产生一条预约和 CREATE 日志；同键不同设备请求并发为一个新建、一个冲突。
- 单学生四设备、跨两个实验室：3 个 201、1 个 409，配额未突破三条。
- 20 个独立学生同步争抢一个时段（MockMvc 完整安全/业务链与真实 MySQL）：1 个成功、19 个冲突、其他错误 0，预约和 CREATE 日志各一条，无重复占用。该测试可由 ReservationCoreIT.bTwentyContendersProduceOneBooking 重复执行。
- 设备/实验室停用与创建同时进行，只出现“创建成功且停用冲突”或“停用成功且创建冲突”，未出现不可用资源上的新有效预约。
- 审批与取消竞争后终态 CANCELLED，日志数与合法动作顺序一致；开始边界的过期与审批竞争后 EXPIRED，无非法批准。
- 撤权事务持有实验室行锁，等待中的审批在提交后重新查权限并返回 403，预约仍 PENDING、没有新增审批日志。
- 真实 MySQL 触发器强制审计插入失败，分别验证新建、审批和过期的主表回滚；去掉触发器后过期可以恢复执行。触发器仅存在于关闭 binlog 的一次性测试容器，finally 删除，未修改正式配置或完整性约束。
- 201 条过期记录跨两批完成，重复作业返回零次变更，没有重复 EXPIRE。

并发使用 CyclicBarrier、CountDownLatch、独立线程/数据库连接和有界 Future 等待，无 Thread.sleep 制造竞争。这里只记录已执行的正确性和数量；未测量生产吞吐、P95 或长时间负载，不宣称性能目标达标。

### 最小契约澄清与调试

- 预约 mine 增加可选 labId 以满足阶段任务筛选要求，始终限定本人；未改变角色和核心规则。
