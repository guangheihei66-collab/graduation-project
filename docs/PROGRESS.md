### 实际实现

- 用户管理：列表筛选/稳定分页、创建账号、姓名和启停更新、BCrypt 重置密码；只允许系统管理员，禁止更改用户名/角色、停用当前自己和物理删除。
- 实验室：列表、详情、创建、名称/地点/描述及启停更新，编号唯一且不可变；学生仅启用实验室，实验室管理员仅分配范围，系统管理员全局。
- 管理员分配：查询、多管理员替换、空数组撤销；只接受已启用的 LAB_ADMIN，拒绝重复、错误角色、停用或不存在账号；同一事务保证替换失败后旧分配不丢失。
- 设备：列表及详情、创建、修改字段和状态，筛选实验室、名称/资产编号、分类、状态；资产编号唯一且不可改，所属实验室不可迁移，不提供物理删除。
- 列表 SQL 直接附加真实 lab_admin 数据范围；详情和写操作在 Service 再校验范围。学生只看到启用实验室中的 AVAILABLE 设备。
- 实验室行锁协调设备写入、实验室修改和授权替换，锁后再次检查授权；设备及账号按约定顺序加锁，不使用 Java 内存锁或全表锁。
- PATCH DTO 使用 setter 记录出现标记，缺省不更新，可空字段显式 null 可清空；其他必填字段 null、空白必填字符串、空更新和不可变字段返回 400。
- 输出使用 DTO，ID 为字符串，分页统计为数字，日期带 +08:00；用户响应不含密码哈希及微信标识。参数类型/枚举、路径 ID 和方法校验错误补充统一 400 处理。
- ResourceStateGuard 提供实验室停用和设备切换不可用的扩展入口，当前基础实现不查询预约，不代表已有预约占用阻断完成。
